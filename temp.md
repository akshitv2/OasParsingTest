In the OpenAPI Specification (OAS 3.0 and 3.1), advanced parameter serialization is handled via the combination of two
fields: `style` (defining how the values are delimited) and `explode` (defining whether arrays/objects generate multiple
parameters or a single compound parameter).

Here is a complete, minimal OpenAPI 3.1.0 specification followed by the exact HTTP request paths generated by each
combination.

### OpenAPI 3.1.0 Specification

```yaml
openapi: 3.1.0
info:
  title: Parameter Serialization Showcase
  version: 1.0.0
paths:
  /users/{id}:
    get:
      summary: Path style examples (Matrix and Label)
      parameters:
        # Matrix Style, Explode False
        - name: id
          in: path
          required: true
          style: matrix
          explode: false
          schema:
            type: array
            items:
              type: string
      responses:
        '200':
          description: OK

  /items/{tags}:
    get:
      summary: Path style examples (Label with Dot-Prefix)
      parameters:
        # Label Style, Explode True
        - name: tags
          in: path
          required: true
          style: label
          explode: true
          schema:
            type: array
            items:
              type: string
      responses:
        '200':
          description: OK

  /search:
    get:
      summary: Query style examples (Delimiters and DeepObjects)
      parameters:
        # Space Delimited
        - name: colors
          in: query
          required: false
          style: spaceDelimited
          explode: false
          schema:
            type: array
            items:
              type: string
        # Pipe Delimited
        - name: flags
          in: query
          required: false
          style: pipeDelimited
          explode: false
          schema:
            type: array
            items:
              type: string
        # Deep Object Serialization
        - name: filter
          in: query
          required: false
          style: deepObject
          explode: true
          schema:
            type: object
            properties:
              status:
                type: string
              role:
                type: string
      responses:
        '200':
          description: OK

```

---

### Request Examples

Given the input data below, here is how each configuration resolves into an actual HTTP request:

* **Array input:** `["admin", "user"]`
* **Object input:** `{"status": "active", "role": "editor"}`

#### 1. Path Parameters (`in: path`)

| Style                    | Explode | Input | Resulting Request Path     |
|--------------------------|---------|-------|----------------------------|
| **`matrix`**             | `false` | Array | `/users/;id=admin,user`    |
| **`matrix`**             | `true`  | Array | `/users/;id=admin;id=user` |
| **`label`**              | `false` | Array | `/items/.admin,user`       |
| **`label`**              | `true`  | Array | `/items/.admin.user`       |
| **`simple`** *(Default)* | `false` | Array | `/users/admin,user`        |

#### 2. Query Parameters (`in: query`)

| Style                  | Explode | Input  | Resulting Request Query String                           |
|------------------------|---------|--------|----------------------------------------------------------|
| **`spaceDelimited`**   | `false` | Array  | `/search?colors=admin%20user` *(or `colors=admin+user`)* |
| **`pipeDelimited`**    | `false` | Array  | `/search?flags=admin%7Cuser` *(or `flags=admin           |user`)* |
| **`deepObject`**       | `true`  | Object | `/search?filter[status]=active&filter[role]=editor`      |
| **`form`** *(Default)* | `true`  | Array  | `/search?colors=admin&colors=user`                       |
| **`form`** *(Default)* | `false` | Array  | `/search?colors=admin,user`                              |


Not at all. While the delimiters (like spaces and pipes) only affect arrays, `style` and `explode` also radically change how **JSON Objects** (key-value pairs) are serialized into the URL.

When applied to an object, `explode: true` breaks the object's properties out into individual, top-level parameters, whereas `explode: false` packs the entire object into a single parameter string.

Given this object input:
`{"role": "admin", "age": 30}`

Here is how those exact same style rules apply to non-array object data:

### Object Serialization Examples

#### 1. Path Parameters (`in: path` for `name: user`)

| Style | Explode | Resulting Request Path | Breakdown |
| --- | --- | --- | --- |
| **`matrix`** | `false` | `/users/;user=role,admin,age,30` | Comma-separated key,value pairs under the parameter name. |
| **`matrix`** | `true` | `/users/;role=admin;age=30` | **Explodes** the object properties into separate semicolon-separated parameters. |
| **`label`** | `false` | `/users/.role.admin.age.30` | Dot-separated key,value stream. |
| **`label`** | `true` | `/users/.role=admin.age=30` | **Explodes** properties into dot-prefixed assignments. |
| **`simple`** | `false` | `/users/role,admin,age,30` | Plain comma-separated key,value stream. |
| **`simple`** | `true` | `/users/role=admin,age=30` | Plain comma-separated property assignments. |

#### 2. Query Parameters (`in: query` for `name: user`)

| Style | Explode | Resulting Request Query String | Breakdown |
| --- | --- | --- | --- |
| **`form`** *(Default)* | `false` | `/search?user=role,admin,age,30` | The parameter name equals a flat, comma-separated list of keys and values. |
| **`form`** *(Default)* | `true` | `/search?role=admin&age=30` | **Explodes** completely. The parent parameter name (`user`) vanishes, and properties become direct query parameters. |
| **`deepObject`** | `true` | `/search?user[role]=admin&user[age]=30` | Retains the parent name and uses standard application/x-www-form-urlencoded bracket notation. |
